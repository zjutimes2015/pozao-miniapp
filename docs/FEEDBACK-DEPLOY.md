# 反馈闭环 · 部署指南

> 反馈闭环 = 用户提意见 → 你收到结构化数据 → 处理 → 闭环。
> 本文档说明**在微信开发者工具里具体怎么操作**，以及每一项为什么这么设计。

---

## 一、云数据库集合：feedback_items

### 创建步骤

1. 打开微信开发者工具 → 顶部「云开发」按钮 → 进入云开发控制台
2. 左侧「数据库」→ 点「+」新建集合
3. 集合名填 **`feedback_items`**（必须完全一致，云函数按名字找）
4. 权限设置选 **「仅创建者可读写」**
5. 确定

### 为什么是「仅创建者可读写」

小程序云开发默认权限有三档：

| 权限 | 含义 | 是否适合 |
|---|---|---|
| 所有人可读 | 任何人能拉全部反馈 | ❌ **绝不能**，等于公开用户数据 |
| 仅创建者可读写 | 只有 openid 对应本人能读写 | ✅ **选这个** |
| 所有用户可读仅创建者可写 | | ❌ 前端根本不需要读 |

**本项目只需要写入 + 你的管理端读取**，小程序端从不读反馈。
所以「仅创建者可读写」既够用又安全。

> ⚠️ 如果集合建成「所有人可读」，等于把所有人的反馈内容公开。
> 这在提审时属于明显的数据安全缺陷。

### 索引建议（可选但推荐）

反馈量上万后按状态筛选会变慢，建议建两个索引：

| 索引字段 | 用途 |
|---|---|
| `status` | 后台按「未处理 / 已处理」筛选 |
| `createdAt` | 按时间倒序看最新 |

在云开发控制台 → 集合 → 索引管理 → 添加索引。

**上线初期不需要**，几千条以内全表扫描也够快。

## 二、云函数：saveFeedback

### 部署步骤

1. 在开发者工具的项目目录中找到 `cloudfunctions/saveFeedback/`
2. **右键点击该文件夹 → 「上传并部署：云端安装依赖」**
3. 等待完成（约 20-40 秒，会安装 wx-server-sdk）
4. 在云开发控制台 →「云函数」列表里确认 `saveFeedback` 状态为「正常」

### 注意：必须选「云端安装依赖」

如果选「上传所有文件」，`node_modules` 不会被正确处理，云函数会报
`Cannot find module 'wx-server-sdk'`。

**判断有没有传对**：在云开发控制台点开 `saveFeedback` → 「函数代码」→
能看到 `node_modules` 目录就对了。

## 四、数据结构

### 写入的字段

| 字段 | 类型 | 来源 | 说明 |
|---|---|---|---|
| `feedbackType` | string | **用户选择** | `bug` / `suggestion` / `question` / `other` |
| `content` | string | **用户填写** | 必填，≤ 500 字 |
| `contact` | string | **用户填写** | 可空，≤ 100 字 |
| `pagePath` | string | 页面 | 从哪个页面提交 |
| `sessionId` | string | 页面 | 会话标识，便于串联同一次使用 |
| `typeCode` | string | 页面 | 指纹短代码，结果页提交时带上 |
| `createdAtMs` | number | 客户端 | 客户端时间戳（毫秒） |
| `source` | string | 页面 | `fingerprint` / `profile` / `solo` / `train` / `versus` |

### 服务端写入的字段（前端无法伪造）

| 字段 | 值 | 说明 |
|---|---|---|
| `openid` | `getWXContext().OPENID` | **只从服务端取**，前端传什么都忽略 |
| `status` | `new` | 默认「未处理」 |
| `category` | `unclassified` | 默认「未归类」 |
| `priority` | `normal` | 默认「普通」 |
| `createdAt` | `db.serverDate()` | 服务端时间，可排序 |
| `updatedAt` | `db.serverDate()` | 服务端时间，便于追踪处理时间 |

### 为什么 openid 必须落库（与本项目其他云函数不同）

项目里已有的 `identity` 云函数**拿到 openid 但不落库**，
因为它服务于「零采集」定位。

`saveFeedback` 不同：反馈闭环要求「同一用户多条反馈可归组」，
否则无法判断「这是同一个人反复反馈」还是「一群人各报一次」。

**这是两种不同的合规判断**：
- `identity` 回避身份 —— 房间归属用匿名串就够
- `saveFeedback` 最小化使用身份 —— 只存 openid，不存昵称/头像/手机号

需要在隐私政策里说明：**「反馈会记录你的微信 openid 用于关联同类问题，不收集其他身份信息」**。

## 五、你在后台怎么用

### 筛选未处理的

云开发控制台 → 数据库 → `feedback_items`，添加筛选条件：

```
status == "new"
```

按 `createdAt` 倒序排列，最新的在最上面。

### 常见筛选维度

| 想看什么 | 筛选条件 |
|---|---|
| 待处理 | `status == "new"` |
| 问题类 | `feedbackType == "bug"` |
| 结果页的质疑 | `source == "fingerprint"` |
| 特定指纹短代码 | `typeCode == "PZ-XX-1234"` |
| 留联系方式的 | `contact != ""` |

### 处理完记得更新状态

处理完一条，把 `status` 改成 `resolved`（或 `closed`），
后台就只看 `new` 的了。`category` 可以改成 `ui` / `content` / `logic` 等。

**用控制台直接改就行**，不需要另写后台。

## 六、安全设计（为什么这么写）

### 前端校验不是安全边界

`utils/feedback.js` 和云函数做了**同样的校验**，不是重复：

- 前端校验 → 让用户**立刻**看到错误，不用等网络往返
- 云函数校验 → 真正的防线（前端可被篡改、接口可被直接调用）

测试里有一项专门检查**前后端字段上限是否完全一致**，
不一致会出现「前端过了后端拒」的错位。

### openid 不可伪造

云函数**不解构** `event.openid`：

```js
const { OPENID } = cloud.getWXContext();  // 只认这个
```

即使有人直接构造请求体传 `openid: "别人的"`，也会被忽略。

测试项 `云函数忽略前端传入的 openid` 会扫描源码，
一旦有人写成 `const { openid } = event` 立刻报错。

### 限流

单用户 1 次 / 5 秒。防止脚本刷库。
沿用项目里 `versus-service` 的限流模式（1 次 / 3 秒，稍宽松）。

### 离线降级

云开发不可用时，反馈**进本地队列**而不是报错。

**理由**：反馈入口一旦因云服务问题报错，用户会认为产品坏了。
「反馈晚点到」比「反馈入口消失」好得多。

- 队列存 `pz_feedback_pending`，最多 20 条
- 在「我的」页 `onShow` 时自动补传
- 用户点「清空全部数据」时**会一并清掉队列**

### 用户输入也过合规

`content` 提交前会跑 `compliance.checkText`。

**理由**：若用户自己写违规内容入库，审核时整站被扫，责任在平台。
不因为是用户输入就豁免。

## 七、验收清单

部署完成后，逐条确认：

- [ ] 云开发控制台能看到 `feedback_items` 集合
- [ ] 集合权限是「仅创建者可读写」
- [ ] 云函数列表里 `saveFeedback` 状态正常
- [ ] 结果页点「结果有问题？说一声」能进反馈页
- [ ] 我的页菜单第一项能进反馈页
- [ ] 不选类型直接提交 → 提示「请选择一个类型」
- [ ] 内容留空提交 → 提示「请写点具体内容」
- [ ] 正常提交 → 提示「已收到」并返回上一页
- [ ] 云开发控制台里能看到刚提交的记录
- [ ] 记录的 `openid` 有值、`status` 是 `new`、`category` 是 `unclassified`、`priority` 是 `normal`
- [ ] 断网提交 → 提示「已记录」，我的页显示「N 条待提交」
- [ ] 恢复网络后进「我的」页 → 队列自动清空

## 八、常见问题

**Q：提示「云数据库集合不存在」**
→ 集合名拼错了，或者没点「上传并部署」。集合名必须是 `feedback_items`。

**Q：云函数报 `Cannot find module 'wx-server-sdk'`**
→ 部署时选了「上传所有文件」而不是「云端安装依赖」。

**Q：提交成功但控制台里看不到**
→ 检查集合权限。若设为「仅创建者可读写」，管理端能看到（管理端有特殊权限），
但如果你在**小程序代码里**查，那是查不到的 —— 本项目也不需要小程序端查询。

**Q：能不能加图片上传？**
→ 技术上可以（云存储），但会显著增加合规复杂度（图片需审核）。
建议先用文字反馈起步，量起来了再考虑。
