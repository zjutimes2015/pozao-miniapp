## 0. 一句话定位

**一个给 18-35 岁职场成人的论证训练工具：用可量化的能力刻度，证明你的推理能力在移动。**

不是小游戏，不是课程，不是"提升智商"。是一个**测量 + 处方 + 复测**的闭环训练器。

---

## 1. 解决的问题

### 1.1 用户的真实痛点

18-35 岁职场人在日常中反复遇到三件事，但从未被系统训练过：

| 场景 | 具体表现 | 缺失的能力 |
|---|---|---|
| 读方案/合同 | 别人说"数据显示必须做"，问"什么数据、什么口径"就答不上来 | 前提审查 |
| 听汇报 | 一段话听着很有道理，回过神说不清逻辑漏洞在哪 | 论证重构 |
| 自己做判断 | 被"行业都在做""别人都这样"推动，事后发现是错的 | 谬误识别 |

**结论：用户不缺"逻辑知识"，缺的是「知道自己逻辑弱在哪，并且知道怎么练」。**

### 1.2 为什么现在做

- **供给空白**：Brilliant 验证了成人逻辑训练可付费（1000 万学习者，$149/年），但**无中文原生产品**。
- **能力刻度无人做**：中国脑力训练市场 142 亿/年，但逻辑+创造力仅占 22%，且被儿童向占据。成人向无成型供给。
- **平台成熟**：微信小程序 + DeepSeek（¥1/¥2 每百万 token）让「AI 苏格拉底陪练」成本低至**单次 ¥0.006**。

### 1.3 不解决的（明确排除）

- 不解决"智商问题"。人的智力（IQ）不可训练，本产品训练的是**推理表现**。
- 不解决"不会数学"。数量关系、计算能力不在范围内。
- 不解决"表达/写作/沟通技巧"。这是训练逻辑，不是训练表达。

## 2. 目标用户

### 2.1 主画像：28 岁互联网从业者

- **收入**：15-40 万/年，有付费能力但克制
- **痛感**：每周读 3-5 份方案，被"逻辑不清晰"评价过，自己却说不清哪里不清晰
- **碎片**：通勤 20-30 分钟、午休 10 分钟
- **设备**：iOS 约 55%，Android 约 45%（影响变现设计）

### 2.2 触发时刻（用户会打开的时刻）

1. **被质疑后**：会上说方案被问住了，回家想弄明白自己错在哪
2. **读到坏论证后**：刷到一篇漏洞百出的行业文章，想找出来
3. **周期性自检**：月度复测提醒，看到自己的刻度有没有移动

> **设计原则**：时刻 1 和 2 是"被动触发"（无推送），时刻 3 是"主动推送"。V1 依赖前两个 + 一个固定提醒时刻。

### 2.3 明确不服务的用户

- 未成年人及家长（K12 学科培训红线 + 需监护人入口 + 双用户设计）
- 备考型用户（考公/考研——那是应试培训，红线高且已有巨头）

## 3. 核心机制：能力刻度闭环

**这是产品唯一的壁垒。所有功能都必须服务于"让用户看到刻度在动"。**

```
首次测评（20题，5分钟）
    ↓
12 维能力刻度（雷达图）
    ↓
AI 诊断薄弱项 → 生成 30 天训练处方
    ↓
每日 1 题识别训练 + AI 苏格拉底陪练（免费）
    ↓
每周复测 3 题（嵌入式，不打断）→ 刻度移动
    ↓
月度深测：写一段论证，AI 对比 12 类谬误模式
    ↓
【传播层】刻度报告卡 → 分享 → 新用户进入
    ↑____________________________________|
```

### 3.1 关键设计决策：传播层不是独立玩法

裂变**不作为拉新玩法存在**，而是刻度闭环的自然下游。

原因（这是本项目最重要的架构决策）：

- 独立裂变玩法需要"单次 60 秒炸裂"，而能力刻度需要"连续 30 天"。两者时间尺度冲突，会导致**两边都废**。
- 把裂变放在刻度下游后：用户因为"看到刻度移动"而内驱完成 30 天，完成后自然产生炫耀动机 → 分享是结果而非目的。

### 3.2 关键设计决策：付费墙不卡在价值展示之前

- **能力刻度（雷达图、12 维得分、前后曲线、百分位对比）永久免费**——这是留存钩子，卡住就死。
- **付费点下移到"未来 30 天处方"**：具体练什么、为什么给你这道题、薄弱项诊断依据。

### 3.3 关键设计决策：交互界面必须是"论证推理图"，不是选择题

**依据：Brilliant 深度研究报告（2026-10-10）**

Brilliant 的核心交互是"把抽象概念变成可操纵的物理模型"——天平式代数、可拖动的切线、负数数字块。其数学正确性由**代码搭建的确定性交互组件**保证，AI（Koji）只负责观察用户操作并组织语言。

官方原话："Because of how Koji is connected to Brilliant's overall learning and interactive infrastructure, Koji is **exceedingly unlikely to make a math mistake**."

《立论》的对应设计：

| 项 | 设计 |
|---|---|
| 交互载体 | **论证推理图**：把一段论证拆成「前提卡片」「结论卡片」+ 推理连线 |
| 用户动作 | 拖拽前提卡片到推理链、增删连线、标记推断强度 |
| 出错表现 | 拖错前提 → 引擎在该断点定位逻辑缺口，触发追问 |
| 正确性保障 | 形式类由**推理模式识别器**规则判定；语义类由 ground_truth 比对 |

> **为什么这样设计**：Brilliant 的交互组件是为数学定制的，我们无法照搬也无需照搬。但它证明了"交互 + 陪练"是正确的接缝——《立论》的"论证推理图"就是论证训练领域的"天平"。

## 4. 能力模型（12 维）

### 4.1 三组· 12 类论证谬误

| # | 维度 | 组 | 谬误类型 | 识别标志 |
|---|---|---|---|---|
| 1 | 肯定后件 | 形式 | 肯定后件 | `P→Q, P` 推出 `Q` |
| 2 | 否定前件 | 形式 | 否定前件 | `P→Q, ¬P` 推出 `¬Q` |
| 3 | 合成谬误 | 形式 | 合成/分割 | 各部分好 → 整体好 |
| 4 | 归谬 | 形式 | 归谬法 | 假设结论假，找矛盾 |
| 5 | 诉诸无知 | 论证 | 诉诸无知 | 无证据 → 不存在 |
| 6 | 诉诸权威 | 论证 | 诉诸权威 | 身份替代证据 |
| 7 | 诉诸大众 | 论证 | 诉诸大众 | 人数替代证据 |
| 8 | 诉诸情感 | 论证 | 诉诸情感 | 情绪替代证据 |
| 9 | 偷换概念 | 语义 | 偷换概念 | 同一词前后义不同 |
| 10 | 滑坡 | 语义 | 滑坡谬误 | 极端化后果链 |
| 11 | 稻草人 | 语义 | 稻草人 | 扭曲对方观点 |
| 12 | 归因谬误 | 语义 | 归因谬误 | 相关即因果 |

> 后续版本扩展方向（第 13-16维）：双重标准、诉诸传统、以偏概全、循环论证。

### 4.2 刻度计算

每个维度独立计分：

```
维度得分 = (答对数 + 平滑项) / (总题数 + 1) × 100
```

- **平滑项**：`alpha = 1`（贝叶斯平滑，防止 3 题全对 = 100 分的虚高）
- **总刻度**：`sum(12 维) / 12`
- **百分位**：基于累积对照组（见 §6.3）
- **刻度移动**：本次复测得分 - 上次复测得分，显示为「+4.2」

**难度标定原则**（借鉴薄荷计算思维 8 万用户的经验）：
- 整体正确率目标区间 **48% - 56%**
- 低于 35% = 题目脱离能力区间，制造挫败感
- 高于 70% = 题目太简单，无训练价值

### 4.3 题库生产：形式类程序化，语义类 AI 生成

**这是防幻觉的核心架构**：

| 类型 | 维度 | 生产方式 | 验证方式 | 确定性 |
|---|---|---|---|---|
| 形式类 | 1, 2, 3, 4 | **模板化程序生成** | 构造即正确 | 100% 确定，无幻觉 |
| 论证类 | 5, 6, 7, 8 | AI 生成 | 双模型校验 + 人工抽检 | 依赖流程 |
| 语义类 | 9, 10, 11, 12 | AI 生成 | 双模型校验 + 人工抽检 | 依赖流程 |

**形式类程序生成示例**（肯定后件）：

```js
// 输入：命题 P、Q
// 生成：正确推理（P→Q, ¬Q → ¬P 即否定前件）
//       错误推理（P→Q, P → Q 即肯定后件）作为干扰项
// 验证：真值表穷举，4 种赋值下只有「否定前件」为真
function verifyDenyingAntecedent(P, Q, premise, conclusion) {
  const rows = [[true,true],[true,false],[false,true],[false,false]];
  const deduction = (p, q) => (p === q ? p : !p); // ¬P → ¬Q
  return rows.every(([p, q]) => deduction(p, q) === !conclusion(P(p), Q(q)));
}
```

**管线**：
1. **Generator**：DeepSeek 生成题目 + 标准论证链（ground truth）+ 干扰项设计
2. **Verifier**：第二个模型独立复核——① 答案是否唯一 ② 前提是否充分 ③ 干扰项是否有争议
3. **分歧仲裁**：两模型不一致 → 送人工队列
4. **人工抽检**：10% 抽检，错误率 > 5% 则该维度全部重生成
5. **回归验证集**：人工精标 100 题固定集，每次变更模型/prompt 后全量重跑，一致率 < 90% 不得发布

> **成本控制**：单题生成约 ¥0.01（生成+校验），V1 需 120 题（含每维 10 题），题库总成本约 ¥2。**极低，可大胆迭代。**

### 4.4 V1 题库规模

- **首测题库**：60 题（每维 5 题）→ 首测抽 20 题
- **周测题库**：60 题中每维预留 2 题作为周测（每维 7 题总量）
- **月测**：AI 生成实论证，实时生成
- **合计**：约 90 题硬题库 + 动态生成

## 5. 核心功能：AI 苏格拉底陪练

### 5.1 交互流程

```
用户提交自己的推理（或选"我没思路"）
    ↓
AI 追问 1：针对最薄弱的推理环节提出具体质疑
    ↓
用户回答（1-2 句）
    ↓
AI 追问 2：暴露更深层前提
    ↓
... 3-5 轮
    ↓
AI 揭示：本题标准论证链 + 用户的思维分叉点
```

**关键：AI 永远不自己编造"正确答案"。**
标准论证链来自题库 `ground_truth`，AI 的任务只是**基于 ground truth 追问**。

### 5.2 Prompt 架构

```
System:
你是论证训练教练。你只能基于【本题标准论证链】进行追问。
硬约束：
1. 禁止引入标准论证链之外的知识、案例、定义
2. 禁止在追问中透露结论
3. 禁止使用"正确/错误/答案是"等判定词
4. 你的任务是让用户自己发现思维分叉

【本题标准论证链】{ground_truth}
【本题涉及的谬误类型】{fallacy_type}
【用户当前认知水平】{level}

用户回答：{user_input}

要求：只输出一句追问，不超过 40 字。
```

### 5.3 成本核算

单次训练（约 6 轮对话）：

| 项 | token 数 | 单价 | 成本 |
|---|---|---|---|
| 输入（含 ground truth） | 4,000 | ¥1/百万 | ¥0.004 |
| 输出 | 1,200 | ¥2/百万 | ¥0.0024 |
| **单次** | 5,200 | — | **¥0.0064** |

- 每日 1 次 → 月 ¥0.19 → **年 ¥2.3**
- 1,000 DAU → 年成本约 ¥6,900

> **结论：AI 成本不是瓶颈。** 设计上应大方给用户用陪练，不要用付费墙限制它。

### 5.4 免费版限制的正确形态（借鉴 Brilliant 的结构性教训）

Brilliant 的免费版形态值得逐条对照：

| Brilliant 的做法 | 《立论》采用 | 理由 |
|---|---|---|
| 免费可访问**全部 68 门课**，只限每天 2 节课 | 12 类谬误识别训练**全部免费、无限次、无每日上限** | AI 成本仅 ¥0.0064/次，用频次限制换收入 = 退化成高成本数独 |
| Streak / XP / 联赛**免费用户也有** | 全部成就系统免费 | 付费墙不包住留存机制 |
| Pro 中国区年付 ¥960 / 月付 ¥120 | 处方 ¥49 买断 | 我方定价仅为其月付价 40%，V1 验证期保持不变 |
| 免费试用需先填支付信息，引发大量投诉 | **不做试用**，直接买断 | 见 §8.2 |
| 年付退款窗口仅约 3 天，被投诉至 BBB | **买断制，7 天内无理由退款** | 结构性优于 Brilliant |

## 6. 技术方案

### 6.1 技术选型

| 层| 选型 | 理由 |
|---|---|---|
| 前端 | **原生微信小程序** | 与既有 3 个项目一致，工程习惯统一，无框架层损耗 |
| 后端 | **微信云开发（云函数 + 云数据库）** | 已在《猫在家》《梦镜》验证，运维成本最低 |
| AI | **DeepSeek API**（V4-Flash ¥1/¥2） | 单次成本 ¥0.006，价格最低，中文逻辑推理可用 |
| 降级 | **三级**：云函数(DeepSeek) → 本地规则引擎 → 静态兜底 | 沿用《梦镜》成熟架构，无 API Key 也能功能完整 |
| AI 校验 | **双模型**：DeepSeek 生成 + DeepSeek(不同 prompt) 校验 | 成本仅 ¥0.01/题，比换模型简单且够用 |

### 6.2 三级降级链

```
第1 级：云函数 + DeepSeek
  ↓超时/失败
第 2 级：本地规则引擎（utils/argue-engine.js）
  - 形式类题目：纯 JS 逻辑判定，100% 正确
  - 语义类题目：预置的追问话术模板库
  ↓ 无题库/仍失败
第 3 级：静态兜底（预置 20 题 + 固定解析文案）
```

> **与《梦镜》一致的设计哲学：无 API Key 功能必须完整**，只降级不残废。

### 6.3 数据模型

```
用户 user
├── openid, 首测时间, 当前总刻度, 百分位
├── 12维得分 { d1: {score, n, ts}, d2: ..., d12: ... }
└── 训练记录 training_log[]
    ├── { date, 维度, 正误, 用时, 是否用陪练 }

测评 assessment[]
├── { openid, type: '首测'|'周测'|'月测', ts, 12维得分, 总分, 百分位 }

处方 plan[]
├── { openid, 生成时间, 过期时间, 薄弱项[], 30天安排[], 是否付费解锁 }

对照组 pool[]
├── { ts, 总分 } ← 用于计算百分位，必须有真实样本
```

## 7. 传播层设计

### 7.1 刻度报告卡

**不是**"分享你的题"，而是**分享你的能力坐标**。

卡片内容：
```
┌─────────────────────────┐
│   我的论证能力刻度       │
│   总分 62/100            │
│   超过 78% 的职场人│
│                         │
│   [12 维雷达图]          │
│                         │
│   最强：识别偷换概念      │
│   最弱：归谬法            │
└─────────────────────────┘
```

### 7.2 百分位的真实性约束

> **百分位必须有真实对照组支撑。**

在样本量< 500 前，报告中显示「样本积累中」，**不允许显示百分位**。
用虚假百分位驱动分享是短期自欺，长期会反噬口碑。

V1 目标：6 周内累积 500 测评样本后开启百分位显示。

### 7.3 裂变设计

- 分享文案带参数：`我最强的推理能力是识别偷换概念，你能超过我吗？`
- 分享落地页：展示报告卡 + 「测你的论证刻度」CTA
- 好友对比：可选功能，V1.1（需谨慎，避免社交压力导致放弃）

### 8.1 唯一付费点：AI 训练处方

| 内容 | 免费 | 付费 |
|---|---|---|
| 12 维刻度、雷达图、历史曲线、百分位 | ✅ 永久免费 | — |
| 识别训练题 | ✅ 无限 | — |
| AI 苏格拉底陪练 | ✅ 无限 | — |
| 月度深测（写论证） | ✅ | — |

| **处方推送（每日提醒）** | ❌ | ✅ |

### 8.2 定价与合规

- **定价**：Android ¥49 买断（无订阅，避免续费纠纷）
- **iOS：永久免费**

### 8.3 激励视频

## 11. 验收标准

> 采用**验证型**门槛：**任一项不达标，不上线 / 停手，不加功能救。**

### ① 内容验收

- 形式类 4 维（肯定后件/否定前件/合成/归谬）：程序生成 + 真值表验证，**正确率 100%**
- 语义类 8 维：双模型一致率 **≥ 90%**
- 人工抽检 10%，错误率 **≤ 5%**
- 每题有唯一正确答案，干扰项无争议
- 首测难度标定后整体正确率落在 **48% - 56%**

### ② 功能验收

- 完整跑通：首测 → 刻度 → 处方 → 陪练 → 报告卡 → 分享
- **三级降级链验证**：断开网络 / 删除 API Key，功能仍完整（能出刻度、能陪练、能出报告）
- 本地引擎与云端引擎结果一致（形式类题目）
- **推理模式识别器**：形式类 4 维的推理有效性判定为纯规则，误判率 0%（对齐 Brilliant "AI 极不可能犯错"的标准）
- **论证推理图交互**：拖拽前提/连线/标记全流程可用，无引擎错误

### ③ 体验验收

- 首测完成 ≤ **5 分钟**（20 题）
- 单题作答 → 反馈渲染 **≤ 3 秒**
- AI 陪练首轮响应 **≤ 5 秒**
- 首屏加载 **≤ 1.5 秒**
- 所有页面在 iPhone SE / 主流安卓机无横向滚动
- **每日训练门槛 ≤ 3 题 / 3 分钟**（对齐 Brilliant Streak 设计：低门槛优先于长时长）

### ④ 合规验收

- 类目「教育-素质教育」审核**通过**
- 禁用词全站命中数 **= 0**
- iOS 虚拟支付相关代码/文案 **= 0**
- 隐私政策 URL 已填入后台并可访问

### ⑤ 数据验收（6 周门槛，决定项目生死）

| 指标 | 门槛 |
|---|---|
| 首次测评完成率 | **≥ 40%** |
| 完成 2 次以上复测的比例 | **≥ 15%** |
| D7 留存 | **≥ 12%** |
| 对照组样本量 | **≥ 500**（未达标不开百分位） |

### 17.4 必须公开的能力边界

借鉴Brilliant 的诚实做法，在报告页公开：

> **本产品覆盖 12 类常见论证谬误，约占日常职场论证中高频谬误的 X%。以下情况不在覆盖范围：专业数学/统计学论证、法律条文解释、涉及具体行业术语的技术论证。**

配合公式公开：`(已覆盖 + 0.5 × 部分覆盖) ÷ 常见谬误总数`

**理由**：本项目用户画像是"讲逻辑的人"，数据上的漏洞会被立刻发现。公开边界不是自曝短板，是建立信任。
